# CLAUDE.md

A top-down wave-survival ARPG in vanilla JavaScript and Canvas 2D. Nine classes: Dragonknight, Spellweaver, Ranger, Nightblade, Machinist, Swordsaint, Cleric, Druid, Paladin. There are no dependencies, no build step and no test suite.

## Running

- Run `PlayGame.bat`, which serves the folder with `python -m http.server 8000` and opens `http://localhost:8000`.
- The game `fetch`es `data/*.json`, so it must be served over HTTP; opening `index.html` as a file won't work.
- The dev menu can turn off cooldowns (`devNoCooldowns`).
- The **Training Room** (the small card in the top-left sea of the dungeon map, `training.js`) is the place to test combos and visuals in the real game: dummies (1 / 2 / 3 at the cursor), per-dummy DPS, ranks and evolutions, the late-game kit, god mode, no cooldowns, a gauge fill. The user plays there too; prefer pointing them to it over describing a setup.

## Code layout

Styles for the in-game UI are in `ui.css` (dark-fantasy panels, HUD, screens); the start menu's styles are inline in `index.html`. Every script is a plain global script loaded by `<script>` tags in `index.html`. There are no modules: functions and state are shared through globals. Load order only matters for code that runs at load time. Cross-file calls happen at runtime, so they're fine in any order. **A new file needs its own `<script>` tag** before `main.js`.

Data lives in `data/`. In `classes.json`, each class has:
- `skills` 1 to 4 (Q, E, Space, R), each with `upgA` / `upgB`, the evolutions chosen at rank 4;
- `weapon`, the basic-attack type;
- `rareWeapon`, whose `rmbSkill` is the right-click ability (handler `SkillRegistry[class].rmb`);
- `rareArmor`, `rareAmulet`, `rareBoots`, `rareGloves`: every class has its own set. The slot sets the base stat (an amulet's `val` is its CDR); an optional `val` overrides it. The amulet feeds the class gauge or a spell, the boots the Space skill, the gloves the basics.

`enemies.json` and `items.json` hold enemies, dungeons and loot.

## How things work

- **Skill slots:** 1 = Q, 2 = E, 3 = Space, 4 = R, `rmb` = rare-weapon ability. A class can define `canCast(slot)` to refuse a cast without spending the cooldown; the Paladin uses this.
- **Power:** every damage bonus (weapon, power orbs, blessings, Frenzy, Momentum, the Reaper...) adds into one number, listed by `powerParts()` in `combat.js`; a hit deals base × rank × Power / 100, then × 0.6 (`HIT_SCALE`). Texts say "+50 Power", never "% DMG". Show players real numbers with `hitDmg(base, rank)`. A new damage bonus goes into `powerParts`, so the Tab sheet lists it.
- **Shields:** grant them with `addShield(amount, time)` (`combat.js`), never `player.shield +=`: stacked shields stop at half the max HP.
- **Dragonknight basic:** `updateHeavySwing` (`skills.js`) replaces the auto-repeating basic: a tap is a light swing, a hold (`player.heavy`) charges an overhead slam that strikes on release (a full charge waits for it). `castBasic(heavy)` passes the charge to the `'sword'` attack and to `onBasicAttack` for the chop animation.
- **Effects:** plain objects pushed to `effects` with `life` / `maxLife`, which `update()` counts down. Gameplay that ticks over time lives in `update()`, matched by `type`. Visuals are drawn by type.
- **Game time vs. real time:** `update(dt)` drives everything that should pause with the game: `fxTime`, particles, timers, effect lives. Animate with `fxTime` or an effect's elapsed time (`maxLife - life`), not `performance.now()`. The exception is idle sprite animation.
- **Draw hooks:** each returns `true` when it handled the object, so legacy drawing is skipped.
  - `drawPlayerProjectile` → `drawSkillProjectile`
  - `drawSkillGround` (under enemies)
  - `drawSkillEffect` (effect layer)
  - `drawUltOverlay` (above everything)
  - Each hook in `skillfx.js` chains into the E, Space, R and weapon-ability files. Add new visuals there instead of growing `main.js`.
- **One-shot bursts inside a draw function:** guard them with an `ef.burstDone` flag.
- **Sprite frame:** characters and weapons are drawn in a local frame where **+x is the facing direction** and +y is the character's right side.
- **Camera and world coordinates:** maps in `STAGE_MAPS` (the three Slime Caves stages: the clearing, waves 1-5; the cavern, 6-10; the hive, 11-15) are bigger than the screen and scroll; every other map is still exactly the window with the camera at 0,0. `draw()` translates by the camera, so anything drawn in screen space (overlays, vignettes) must come after the world's `ctx.restore()`. `mouseX` / `mouseY` are **world** coordinates (screen mouse + camera); use them for aiming as before.
- **Obstacles:** `clampToBounds` also pushes things out of the map's solid obstacles, so every movement path respects them. Anything with `airborne = true` (or the player with `player.z > 4`) passes over.
- **Cave terrain:** on maps with a `grid` (`currentMap.grid`), each 25 px cell is floor, wall, lake, ravine or seal.
  - Walls and the seal block everything, including leaps.
  - Ravines block walking but not airborne things or shots.
  - Lakes can be walked through, but they slow and poison the player (`player.wading`; the Hazard Suit ignores this).
  - Shots that fly into rock end there (`shotHitsWall`); orbiting, returning and stationary ones are exempt.
  - `startDash` clips a dash at the first wall. A dash or charge that rams a wall, or the Amalgam's stampede into one, drops stalactites that hurt the player and enemies.
  - Brood pods (hive) are enemies of type `brood_pod` with `e.pod` set, so every attack can pop them. They aren't wave enemies (`checkEnemyDeath` hands them to `podPopped`), the enemy loop skips them, and the HUD cover check ignores them. But popping one during a wave kills the slime waiting inside: `podPopped` lowers `enemiesToSpawn` (a boss wave keeps its last spawn, which brings the boss), so clearing pods first shortens the wave.
  - Enemies walk straight at the player when the line is clear; otherwise they follow the flow field (`navSteer` in the enemy loop). Ranged AI aims along the real line and holds fire without a clear shot.
- **Stage events:** while a blocking `stageEvent` runs, `update()` only advances the scene, particles and effect lifetimes, and skill input is ignored. Events: `boss_intro` (Slime King leaves the cave), `amalgam_form`, `seal_break`, `queen_wake`, `queen_throes`, `trophy_claim`, `cave_exit` (the hero fades out with `player.fadeOut`, then the screen with `player.exitFade`). The camera follows `camera.tx/ty` while they're set; in the hive it also leans toward the Queen while she sits on her throne.
- **Wave flow:** regular waves roll on by themselves. When one is cleared, `onWaveCleared` starts a 4 s breather (`waveBreak`; the wave plaque counts it down), then `startNextWave` runs mid-fight with the usual 30% heal. Only a boss stops the run: the stage exit on stage maps, otherwise the boss-cleared screen with the shop. `startNextWave` resets the hero's kit (Paladin hammer, Druid companion, a dash in progress) only for a new run, a new map or after a screen, never between regular waves. The inventory (I) can be opened any time in a fight and pauses the game.
- **Stage endings:** after each stage boss, `onWaveCleared` opens the exit instead of showing the boss-cleared screen. Clearing: the cave lights up. Cavern: the seal breaks. Hive: the Queen's death never reaches `showVictory` directly; `queenDefeated` drops her crown, and `startTrophyClaim` shows Victory once you walk onto it.
- **Hive Queen fight (`ai.js`):**
  - Above 60% HP she lobs eggs (they hatch where they land) and spits pink balls.
  - Between 60% and 30% her guards shield her. Strikes on the hero's spot: 0.85 s warning, 2.3 s apart, a breather after a hit.
  - Below 30% she leaps (`state: 'leap'`) to land 220-350 px from the hero, about every 4 s.
  - At 0 HP: `death_throes`, a 14 s escalating bullet hell from the throne. More spiral arms, faster volleys, a counter-spiral, then rings.
- **Enemy flags:** `flyUntil` hides an enemy while it's still a `goo_arc` in the air (flung minions, eggs); `spawnT` / `spawnMax` is the bubble-up while it can't act; `dazed` (Amalgam minions) pauses its AI; `submerged` (the Amalgam's Undertow, under the floor) makes it untouchable: `applyDamage`, player shots, `getNearestEnemyFromPoint` and body-blocking all skip it.
- **Projectiles:** `rampFrom` / `rampTo` (with `ox`, `oy`) make a shot speed up once it is that far from where it was fired; the Queen's bullet hell uses it so distance isn't safety.
- **Performance:**
  - Big static art is painted once into cached canvases (map ground, lake and pool surfaces, slime bodies).
  - Darkness is drawn at half resolution and lights only the first 40 projectiles.
  - HUD orbs repaint at 30 Hz.
  - Keep per-bullet drawing to flat fills (no gradients), since bullet hells put hundreds on screen.
- **Forced movement:** `player.dash` is timed travel with an optional jump arc; `player.grappleTarget` is speed-based pull/charge. Both bypass WASD movement in `update()`. Enemies aren't pushed by the hero's body during a dash (that used to carry a boss along under a Vault), and a leap (`arc > 0`) that comes down inside a body slides on until clear (`clearLanding`, after `onArrive`).
- **Druid companion (`druid.js`):**
  - `player.wolves[0]` is your own companion and never leaves. Spirit animals (Call of the Wild: 12 s, Kindred Howl: 8 s) follow it in the array with a `life`, and a ring under each drains as their time runs out. All of them are untargetable, and the code calls them "wolves" whichever beast was picked.
  - You never steer the companion; that's deliberately not the Swordsaint's blade loop. The only call is the Space finisher (Pounce Strike); Spirit Leap leaves it on its prey and Bramble Snare doesn't send it (playtest: it used to abandon a nearly dead enemy). It hunts prey within 450 px of the Druid: snared (rooted) enemies first, then Scented ones (hit by the Druid in the last 3 s; `applyDamage` calls `druidOnHit`), then the closest. Spirits avoid prey another wolf already has, so they spread over a pack; your own wolf never gives way. Wolves push apart (`separateWolves`) and wait out a Crystal Slime's reflect barrier.
  - Bites are `calcDmg(basicDmg) × 1.25` with damage source `'wolf'`, so they scale like a basic attack (Power, gloves' attack speed), not with skill ranks. Bites on Scented prey fill Bond; at 100 the next bite is a Maul. Bond carries over between waves.
  - Keep the companion near half of the class's damage. It's hands-free, so it keeps hitting through boss mechanics (the Machinist's turrets at ~70% melted bosses).
  - The companion is picked on a screen right after the Druid on the carousel (`showCompanionChoice`, `player.companion`): wolf or black jaguar. Same kit and damage per second. `COMPANIONS[id].rhythm` (1.5 for the jaguar) slows its bites and scales bite damage, Bond per bite and Bloodrage healing to match (Pounce Strike adds a fixed 2 wolf bites, so it gains the same for both); the Maul's bonus shrinks so Maul damage matches too. The jaguar pounces onto prey 60-230 px past its reach. `applyCompanionText` swaps the run's texts (wolf → jaguar, dire wolf → elder jaguar, howl → roar); the E/R icons (`icBeastHead`) and chips follow.
  - Its stuck check only counts when it's out of reach and not moving. An obstacle nudging it at its prey used to send it bounding back to the Druid every second.

## Conventions

- Source files use **CRLF** line endings (git `core.autocrlf=true`); keep them that way when editing. In Git Bash, `sed -i` silently turns a file into LF, and `grep -c $'\r$'` can't see the difference; check with `git ls-files --eol` (every file should read `w/crlf`).
- Match the surrounding style: terse lines, short comments that explain *why*, no external libraries.
- Art direction:
  - Read everything as a strict top-down view. For example, a jaw opens by foreshortening the upper jaw, never by splitting sideways into a V.
  - Hits should feel punchy but stay readable; keep screen shake subtle.
  - No floor-crack decals; the owner doesn't want them. Use glows, scorch marks, sigils or runes instead.
- Git: version branches up to `v1.6`; since v1.7 the work is committed to `master`. Commit messages like `v1.6.2 - The paladin added.`
